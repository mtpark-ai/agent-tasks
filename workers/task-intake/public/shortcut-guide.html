IOS SHORTCUT

安装指南

当前部署尚未绑定一个经过审核的 iCloud Shortcut 或 Apple 验证的 .shortcut 文件。

返回 Setup Portal

WHY

这里不会动态生成 Shortcut 二进制

动态把 Endpoint 或 Token 注入未知二进制会破坏可审计性，并可能把凭据留在下载缓存。正确方式是发布一个固定、实际在 Apple 设备上构建并验证过的通用 Shortcut，再通过 Import Questions 收集每个用户自己的值。

BUILD

手工构建动作顺序

  1. 文本：Endpoint 占位值；设置 Import Question “Task Intake Endpoint”。
  2. 文本：Device Token 占位值；设置 Import Question “Device Token”。
  3. 听写文本：语言按需要设置，暂停后停止。
  4. 要求输入：默认答案使用听写文本，以便编辑。
  5. 显示提醒：展示最终文本，允许取消。
  6. 随机数或 UUID：作为 Idempotency-Key。
  7. 获取 URL 内容：POST 到 [Endpoint]/tasks，JSON 中放任务文本。
  8. Headers：Authorization: Bearer [Device Token]、Content-Type: application/json、Idempotency-Key: [UUID]。
  9. 显示结果：展示返回的 Issue URL。

PUBLISH

为部署者提供一键安装

维护者在 iPhone 或 Mac 上完成并重新导入验证后，创建 iCloud 分享链接或导出签名的 .shortcut 文件，然后重新运行 onboarding：

npm run onboard -- --endpoint 'https://your-worker.workers.dev' \
  --shortcut-url 'https://www.icloud.com/shortcuts/…'

也可以通过受保护的 Admin API 更新 shortcut_url，但绝不能把 Device Token 或 Admin Token嵌入公开 Shortcut。
